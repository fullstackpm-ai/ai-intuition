# Point-In-Time Documentation

Point-in-time docs capture intent, proposals, accepted decisions, and historical plans.

They preserve what was understood at the time. They do not define current system behavior unless a living document explicitly points to them as current.

## Current Legacy Point-In-Time Docs

- [`SPEC.md`](../../SPEC.md): original product spec and implementation context.

## Future Locations

- `specs/`: accepted specs.
- `decisions/`: decision records.
- `plans/`: implementation plans and phased work.

When a point-in-time document is superseded, leave it in place and add succession notes in a newer document.
