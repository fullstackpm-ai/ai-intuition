# AI Intuition Brief - 2026-W21

## One-line thesis

Durable AI intuition comes from mechanisms, boundaries, and structural controls rather than summaries.

## 3 belief updates

1. Stop asking whether the model is safe enough in isolation. Ask which layer owns each reliability property: model behavior, harness constraints, tool permissions, or environment boundaries.
2. More approval prompts do not necessarily mean more control. Oversight works when the user is asked to judge the plan, risk, and escalation points they can actually understand.
3. Defending against prompt injection means constraining the whole path from untrusted content to external action, not merely teaching the model to ignore bad instructions.

## New or updated mental models

- Agent reliability stack = model capability + harness policy + tool affordances + environment exposure.
- Oversight granularity should match human judgment granularity.
- Prompt injection risk = untrusted observation x model compliance x tool capability x permission scope x environment exposure.

## New or updated agent design laws

- Assign every agent safety requirement to a structural layer; do not leave high-stakes requirements as model intent alone.
- Use plan approval, risk-tiered permissions, and interruptibility for long agent workflows instead of prompting for every low-level action.
- Treat every external content source as untrusted input and every tool as a capability boundary that needs least privilege, monitoring, and recoverability.

## New failure modes to track

- Layer collapse: treating model alignment as if it also guarantees harness correctness, tool safety, permissioning, and environment isolation.
- Approval fatigue: repeated low-value confirmations train users to approve without reviewing, weakening the control they were meant to provide.
- Instruction laundering: hostile text enters through a trusted workflow object and is converted by the agent into an authorized external action.

## New eval patterns

- Run the same task across controlled variations of harness, tool permissions, and environment exposure to identify which layer actually prevents the failure.
- Replay long workflows with per-action approval versus plan approval and measure user interruptions, missed risky actions, and completion rate.
- Seed realistic workflow data with hidden malicious instructions and test whether the agent reads, propagates, or acts on them under different tool-permission settings.

## Strategy / value-capture updates

- Durable agent products will compete on controlled execution environments and permission architecture, not only model access.
- Open protocols and shared benchmarks can become part of agent defensibility because security properties need to move into common infrastructure.

## Learning experiments / intuition drills

1. Take one risky agent task and map every failure prevention mechanism to model, harness, tool, or environment. Mark any requirement that exists only as prose.
2. Prototype a task flow with twenty tool actions. Compare per-action approvals to upfront plan review plus explicit approval only for irreversible steps.
3. Build a toy inbox agent with read-only, send-with-approval, and unrestricted-send modes. Inject malicious email text and measure whether damage requires tool exposure.
4. For any agent product, ask: which layer would have to fail for this action to become unsafe?
5. For each approval prompt in an agent workflow, ask what judgment the user is actually expected to make.
6. Trace the path from untrusted text to possible external action; every edge is a security boundary.
