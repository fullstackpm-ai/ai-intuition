# AI Intuition Brief - 2026-W30

## One-line thesis

Durable AI intuition comes from mechanisms, boundaries, and structural controls rather than summaries.

## 3 belief updates

1. Stop asking whether the model is safe enough in isolation. Ask which layer owns each reliability property: model behavior, harness constraints, tool permissions, or environment boundaries.
2. More approval prompts do not necessarily mean more control. Oversight works when the user is asked to judge the plan, risk, and escalation points they can actually understand.
3. Defending against prompt injection means constraining the whole path from untrusted content to external action, not merely teaching the model to ignore bad instructions.

## New or updated mental models

- Agent reliability stack = model capability + harness policy + tool affordances + environment exposure.
- Oversight granularity should match human judgment granularity.
- Prompt injection risk = untrusted observation x model compliance x tool capability x permission scope x environment exposure.
- Research replication is becoming an operator workflow, not only an institutional capability.
- Intelligence stack = learned prior + search process + environment model + outcome feedback.
- Inference economics are physical: model behavior rides on multiply-accumulate density, precision, memory movement, and wiring.
- Precision allocation = error budget + area budget + memory-packing budget.

## New or updated agent design laws

- Assign every agent safety requirement to a structural layer; do not leave high-stakes requirements as model intent alone.
- Use plan approval, risk-tiered permissions, and interruptibility for long agent workflows instead of prompting for every low-level action.
- Treat every external content source as untrusted input and every tool as a capability boundary that needs least privilege, monitoring, and recoverability.
- Use LLM-assisted rebuilds of canonical systems as training data for product intuition; implementation exposes constraints that reading papers hides.
- For tasks with clear state transitions and outcome checks, give agents explicit search or replay machinery instead of relying only on one-shot model judgment.
- When designing AI products at scale, reason about the workload shape and precision needs early; architecture choices can create hardware-aligned or hardware-hostile demand.
- Agent and model-serving systems should track where precision matters rather than assuming uniform precision is either safe or optimal.

## New failure modes to track

- Layer collapse: treating model alignment as if it also guarantees harness correctness, tool safety, permissioning, and environment isolation.
- Approval fatigue: repeated low-value confirmations train users to approve without reviewing, weakening the control they were meant to provide.
- Instruction laundering: hostile text enters through a trusted workflow object and is converted by the agent into an authorized external action.
- Paper-only understanding: believing you understand an architecture because you read the result, while missing the operational constraints revealed by rebuilding it.
- Pure-prior overreach: asking a model to intuit an answer where the task actually needs systematic exploration of possible futures.
- Abstraction blindness: optimizing prompts or models while ignoring that latency and cost are dominated by low-level compute and memory constraints.
- Uniform-precision thinking: using one precision posture across a workflow and missing where accumulated error, memory packing, or hardware availability changes the tradeoff.

## New eval patterns

- Run the same task across controlled variations of harness, tool permissions, and environment exposure to identify which layer actually prevents the failure.
- Replay long workflows with per-action approval versus plan approval and measure user interruptions, missed risky actions, and completion rate.
- Seed realistic workflow data with hidden malicious instructions and test whether the agent reads, propagates, or acts on them under different tool-permission settings.
- Select one canonical agent or ML system, rebuild the minimal version with LLM coding assistance, and log every place where implementation friction changes the conceptual takeaway.
- Compare a model-only agent with the same model wrapped in explicit candidate generation, simulation, and scoring on tasks with verifiable end states.
- For a target workflow, estimate token volume, context length, precision sensitivity, and latency budget, then map those to likely compute and memory bottlenecks.
- Run task-level evals across precision and quantization settings, but separately inspect failures that arise from accumulation-sensitive steps.

## Strategy / value-capture updates

- Durable agent products will compete on controlled execution environments and permission architecture, not only model access.
- Open protocols and shared benchmarks can become part of agent defensibility because security properties need to move into common infrastructure.
- Small teams can now use replication depth as a strategic learning advantage, reducing dependence on secondhand frontier commentary.
- Commercial agents should identify which workflows have game-like structure and exploit search there, instead of applying uniform chatbot architecture everywhere.
- The application layer can gain leverage by shaping workloads to fit hardware economics, especially as inference volume grows.
- Infrastructure-aware product teams may build cost advantages by routing workloads to precision regimes that match task tolerance.

## Learning experiments / intuition drills

1. Take one risky agent task and map every failure prevention mechanism to model, harness, tool, or environment. Mark any requirement that exists only as prose.
2. Prototype a task flow with twenty tool actions. Compare per-action approvals to upfront plan review plus explicit approval only for irreversible steps.
3. Build a toy inbox agent with read-only, send-with-approval, and unrestricted-send modes. Inject malicious email text and measure whether damage requires tool exposure.
4. Rebuild a small AlphaGo-like loop or another canonical agent architecture twice: once from prose notes and once with LLM coding help. Compare how much conceptual understanding comes from each path.
5. Take a planning task with explicit constraints and compare direct-answer prompting against tree search over candidate plans with validation after each step.
6. Compare two versions of an agent task: one with long context and high token churn, one with compact state and retrieval. Estimate how each stresses compute versus memory movement.
7. Take a retrieval-plus-generation workflow and test quality/cost under different model sizes or quantization levels; identify which substeps tolerate lower precision.
8. For any agent product, ask: which layer would have to fail for this action to become unsafe?
9. For each approval prompt in an agent workflow, ask what judgment the user is actually expected to make.
10. Trace the path from untrusted text to possible external action; every edge is a security boundary.
11. For any AI paper, ask: what would I only learn by rebuilding the smallest runnable version?
12. For any agent workflow, ask whether the next action should come from intuition, search, or a verifier.
13. For any agent feature, ask: what arithmetic and memory movement does this product decision force at inference time?
14. Ask where errors accumulate in the workflow rather than where individual operations look harmless.
