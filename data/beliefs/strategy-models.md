# Strategy Models

## Frontier capability and commercial deployability are different curves

A capability can exist at the frontier before it becomes reliable, cheap, auditable, and trusted enough for commercial deployment.

## Model capability can commoditize weak application layers

If an application is only a thin wrapper around model output, frontier models and horizontal agents can absorb it.

## Workflow state is a durable source of leverage

Applications become more defensible when they own permissions, audit logs, data schemas, workflow state, user trust, and execution context.

## Horizontal agents threaten interfaces before they threaten systems of authority

A horizontal agent can abstract UI work before it can safely replace systems that own state, compliance, approvals, and irreversible execution.

## 2026-W21
- REFINED: Durable agent products will compete on controlled execution environments and permission architecture, not only model access.
- REFINED: Open protocols and shared benchmarks can become part of agent defensibility because security properties need to move into common infrastructure.

## 2026-W30
- REFINED: Small teams can now use replication depth as a strategic learning advantage, reducing dependence on secondhand frontier commentary.
- REFINED: Commercial agents should identify which workflows have game-like structure and exploit search there, instead of applying uniform chatbot architecture everywhere.
- REFINED: The application layer can gain leverage by shaping workloads to fit hardware economics, especially as inference volume grows.
- REFINED: Infrastructure-aware product teams may build cost advantages by routing workloads to precision regimes that match task tolerance.
